# RqJey Mods — сайт для GitHub Pages

Статический каталог Minecraft-модов. Все моды и версии автоматически берутся из **одного** репозитория GitHub Releases.

## Настройка

В `config.js` укажи:
- `owner` — GitHub username;
- `releasesRepo` — репозиторий, где лежат релизы (сейчас `Minecraft-Mods`).

Репозиторий должен быть публичным, чтобы GitHub API мог читать релизы без токена.

## Как добавлять моды и релизы

Создавай релиз именно здесь: https://github.com/RqJey/Minecraft-Mods/releases

Используй в названии релиза или теге шаблон:

- `Test-Mod-Release`
- `Test-Mod-Release(Что-то написано)`
- `Test-Mod-Release-1.0.0`

Часть до `-Mod-Release` станет названием отдельной карточки/вкладки на сайте: `Test`.

Прикрепи к релизу один или несколько `.jar` файлов и опубликуй его. Сайт автоматически:
1. найдёт новый релиз в общем репозитории;
2. определит, к какому моду он относится по имени/тегу;
3. добавит карточку мода, если её ещё нет;
4. покажет релиз в списке версий именно этого мода;
5. покажет все прикреплённые файлы из выбранного релиза.

Для следующей версии того же мода используй то же имя мода, например `Test-Mod-Release-1.0.1`. Тогда она попадёт в уже существующую карточку `Test`, а не создаст новую.

## Описания и оформление

Для известных модов можно оставить/изменить метаданные в `projects` внутри `config.js` (иконка, категория, описание, версия Minecraft). Новые моды без записи в конфиге тоже появятся автоматически с базовым оформлением.

## Публикация сайта

Загрузи содержимое папки в GitHub Pages и включи **Settings → Pages → Deploy from a branch → main → /(root)**.

Важно: GitHub Releases API по умолчанию отдаёт до 100 последних релизов. Сайт показывает все типы файлов, прикреплённые к релизу.


## Порядок версий и выбор файла

В меню версий релизы сортируются по времени загрузки прикреплённых файлов:
самый поздно загруженный файл определяет релиз, который будет выбран первым.
Внутри релиза файлы также сортируются по времени загрузки — самый новый файл
автоматически выбирается для скачивания.

Для определения времени используется `created_at` GitHub Release Asset
(время загрузки файла). Если GitHub не вернул дату файла, используется дата
публикации релиза. Номер версии в имени файла или теге не влияет на выбор
версии по умолчанию.

Все предыдущие релизы и файлы остаются доступными для ручного выбора.
После публикации нового файла сайт подхватит его при следующем обновлении
списка релизов и будет выбирать его по умолчанию.
